How it works

From inbox to action in milliseconds.

Every email flows through a deterministic pipeline — classification, notification, and security checks happen in pure Python. The LLM only wakes up when you tap a button.

01
AgentMail WebSocket
Persistent connection to AgentMail Cloud. Push-based delivery — no polling, no delays. Subscribes to your inbox and writes each event as a JSON file.
agentmail_ws.py · systemd service
02
ReaderAgent — Sanitization
All email fields pass through sanitize_email_content() — strips HTML, scripts, control characters, tracking parameters. Returns a ReaderOutput dataclass. No raw content escapes.
reader_agent.py · zero LLM
03
ContextQuarantine — Taint Tracking
Registers all email fields with taint metadata. can_persist() = False, can_influence_tools() = False. Email content can never persist to memory or trigger tool execution.
context_quarantine.py
04
PolicyEngine — Authorization
Validates structured intent against trust levels. Suspicious → always block. Unknown → reply blocked. Known → all actions allowed. Allowlisted → log only.
policy_engine.py · policy_config.yaml
05
Telegram Notification
Builds the notification with inline buttons — Reply, Ignore, Save to Vault, Trust Sender. Short keys stored in pending_actions.json. One-time-use, SHA-256 hash-bound callbacks.
agentmail_processor.py · Bot API
06
LLM Engagement — Only on Tap
When you tap Reply or Save, Hermes Agent reads the thread via MCP and drafts a response or saves to Obsidian. Always CCs owner and includes signature. This is the only step that costs tokens.
Hermes Agent · MCP tools
Why it's different

Built for agents that respect your wallet.

Every design decision optimizes for one thing: not spending tokens unless you explicitly ask it to.

Zero-cost notifications

Classification runs on Python heuristics — keyword matching, sender analysis, attachment detection. No LLM call needed to decide whether an email is worth your attention.

WebSocket push delivery

Persistent connection to AgentMail Cloud means instant push notifications. No polling intervals, no missed emails, no delay between arrival and your Telegram chat.

Human-in-the-loop, always

No auto-replies. Ever. The LLM only engages when you tap a button. Every reply is drafted for your review before sending — you remain the final authority.

Five-layer security

Sanitization, taint tracking, policy enforcement, one-time-use callbacks, and SHA-256 hash binding. Email content is treated as hostile until proven otherwise — and even then, contained.

Security architecture

Five layers between email and your agent.

Every email is treated as untrusted input. The pipeline applies defense at each boundary — from raw HTML to LLM context window.

01
ReaderAgent — Sanitization
Tool-less, zero I/O. All fields sanitized before any system sees them.
02
ContextQuarantine — Taint Tracking
Email content can never persist to memory or trigger tools.
03
PolicyEngine — Authorization
Suspicious blocked, unknown restricted, high-risk requires confirmation.
04
One-time-use Callbacks
Each button press consumes its key. Replay attempts are logged.
05
SHA-256 Request Hash Binding
Callbacks bound to original context. Can't be replayed with different parameters.

89 unit tests cover injection scenarios, attachment safety, and output escaping. Full security documentation in SECURITY.md.

Quick start

Running in under five minutes.

Three steps: install, configure, run. Works with any free AgentMail account.

1. Install dependencies

# Python 3.11+ required pip install agentmail websockets

2. Configure environment

# Copy the example and fill in your credentials cp .env.example .env AGENTMAIL_API_KEY=am_us_your_key TELEGRAM_BOT_TOKEN=your_bot_token TELEGRAM_CHAT_ID=your_chat_id AGENTMAIL_INBOX_ID=your-inbox@agentmail.to

3. Install as systemd service

# Deploy as a persistent service mkdir -p ~/.config/systemd/user cp agentmail-ws.service ~/.config/systemd/user/ systemctl --user daemon-reload systemctl --user enable --now agentmail-ws # Send yourself a test email — watch Telegram light up
